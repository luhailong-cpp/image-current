# 主城正式游戏图并行制作

用户已确认自然灰石地面、春节建筑与局部细节方向，并明确要求开多个窗口制作。四个用户可见窗口分别拥有西北、东北、西南、东南分区。

先读 production-contract.json。画布采用用户当前 AGENTS.md 明写的65536×65536，16×16个4096正式块；这仅确定美术像素坐标。5000人世界尺寸、角色占地和客户端接入独立待验证，不得把画布规格当成容量通过。旧39/70库存不计入新布局。

所有生图只用内置image_gen，无单独计费API。模型/质量目标读取config，但工具未披露实际值时必须记录null。每张图/重试均保存实际prompt、输入角色、来源哈希、原生尺寸与回执。

每个窗口只写自己的zone子目录，每个tile内部按原生子片连续扩展。4×4个1024核心+每边115上下文是1254原生的工作方案；实际返回若不同必须据实调整坐标覆盖，不能拉伸凑数。先生成首个真实原生片，再以其作为相邻片的重叠参考顺序扩展，不允许16张互不相关随机图直接拼合。

允许按本项目切图规范使用现有机械裁切/拼接工具处理已经生成的原生像素。布局引导图必须明确标记为layout-only，不作为游戏画质。拼接不扩大原图，不靠模糊遮盖道路/屋檐错位。先内部16片，再外部块边缘。未满足条件的写candidate或partial，不能写完成。

分区像素框：NW=[0,0,32768,32768]；NE=[32768,0,65536,32768]；SW=[0,32768,32768,65536]；SE=[32768,32768,65536,65536]。行列均从1开始；tile origin=((c-1)*4096,(r-1)*4096)。四区有重叠上下文但最终核心不重复计数。

先推进指定首块，再从已有片连续扩展本区。各窗持续制作原生素材与拼接，不能只写规划文档或把近景示意图改名当正式块。用户可见子任务不得擅自给其他任务发消息，状态写本区progress.json，root读取汇总。

清理旧主城图片由root单独执行，窗口不得删除旧图库或当前共用参照，不能修改客户端、Git提交或推送。
