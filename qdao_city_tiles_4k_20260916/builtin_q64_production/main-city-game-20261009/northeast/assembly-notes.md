# 东北分区原生核心拼接基线

`assemble.py` 读取当前 `production-contract.json` 和本区图块的 `coordinates.json`；不导入或修改 `production.py`，不修改 `progress.json`。默认图块为 `r05_c13`。脚本只选用 `native/p11.png` 到 `native/p44.png`；其他版本或返修文件列为未选用来源，不擅自替换。

使用仓库当前制作脚本指定的 Python 环境。先只读检查：


去掉 `--check` 后导出基线及 QA。可用 `--tile r05_c13` 显式指定图块；仅接受东北分区行1–8、列9–16。导出仅写本图块的 `qa/core-baseline/<输入签名前20位>/`；不同来源或脚本版本进入不同快照目录，不会把旧完整候选混入新的缺片状态。进程退出码：0为检查/导出成功（允许缺片），1表示有无效来源，2表示坐标或执行失败。退出码0不是视觉验收通过。

## 像素与来源规则

每张有效输入必须实际解码为1254×1254、不透明RGB/RGBA PNG；生成记录的尺寸、SHA256、当前坐标、未缩放声明、请求、完整提示词、回执、参考图哈希均核对。提示词正文必须与请求一致，仅允许文本文件多一个结尾换行并明确记录；实际提交文本仍保存在request.json。记录中的配置目标、提交参数与实际模型/质量分别保留；未知实际值保持null。原工具输出仍存在时核对字节一致；已删除时据实标记未复验，不推断仍能读取。

每张只取 `[115,115,1139,1139)` 的1024²核心，按整图坐标作整数粘贴。输出4096² RGBA，缺失或无效片区域为透明，绝不使用layout-only像素补空。无缩放、无羽化、无调色、无模糊；全部24段内部接缝因此仍可能明显，等待视觉检查或原生重绘。

只有16张选定来源全部有效时才另写不透明RGB文件 `r05_c13-core-baseline.candidate.png`。这是结构完整的4K候选，不是已验收图块。统计中的 `formalAcceptedCount` 永远为0；脚本不修改客户端、世界尺度或5000人验证状态。

## 导出内容与查看顺序

- `partial-core-baseline.rgba.png`：原像素拼接基线，透明区代表尚未生成或来源无效。
- `assembly.json`：所有来源、回执、请求、参考图、坐标与输出的尺寸/hash；缺失及无效原因；生成文件数、有效选定片数、覆盖率、完整候选数。
- 每对已齐全相邻片的 `*-join-100pct.png`：跨接缝384像素宽或高的原尺寸裁剪。
- 对应 `*-overlap-comparison-100pct.png`：同一230像素共享范围的两个原生版本，竖缝左右并排、横缝上下并排，无混合；均值和P95差异仅作定位诊断。
- 9个四片交点的900²原尺寸裁剪（至少有一片时生成）以及3条完整横缝、3条完整竖缝的原尺寸检查条。

先检查整体坐标与缺口，再逐段看台阶、屋檐、栏杆、石缝、阴影和四片交点。完成内部24段接缝检查后仍需外部4K邻块接缝检查；低差异数值、16片齐全或PNG导出成功均不代表视觉验收。跨分区接缝由根任务最终复核。

本脚本不主动清理输出快照。制作任务在成品落盘、当前引用齐全后按AGENTS.md清理中间图，并保留必要的文字来源证据。
