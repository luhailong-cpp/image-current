本目录检查的是当前已确认主城、渔村、八仙岛预览中的**人工保守可见地面**，用于尽早发现面积、角色比例和通路疑点，减少后续返工。它不是新的游戏地图，也不是容量验收。

**当前结论：部分试验尺寸能排入 5000 个角色脚点，但三图的连续通行、门洞连接、人物遮挡与运行性能均未验收。`capacity5000Validated` 和 `worldSizeApproved` 仍为 `false`。** 现有美术不能据此直接判定为整图重画；世界尺度调整仍须审核人物与建筑、门洞、道路的比例。

## 方法与实验参数

1. 实际查看三张 1254×1254 已确认预览，对明确可见的铺装、广场、院落、台阶和部分木平台作多边形标注；扣除屋顶、墙、树、水面与明显障碍。被屋檐、门楼遮挡的地面不强行补出。
2. 对地面多边形联合减障碍，按四邻接像素计算连通分量。只在**最大的可见连通分量**内排站位，不将分离小块面积混入站位容量。
3. 主城试验边长为 **600、700、800、900、1000、1100 世界单位**。每组中渔村和岛的世界面积各为主城 **0.75**，因此边长各为主城的 `sqrt(0.75)≈0.866025`，不是边长乘 0.75。
4. 试验使用 **5 或 6 世界单位的方形脚点间距**，比较四种网格起点，选择当前采样中站位较多的一种。每个脚点以 **1.45 世界单位半径**的中心及 20 个周边样本检查可见地面，作为阴影落脚范围的近似检查。这不是精确碰撞膨胀或导航宽度测试。
5. 预留 **20% 候选站位不使用**，可用数量为 `floor(候选站位×0.8)`，最多选择 5000 个实际坐标。20% 空置相当于比人数多 25% 的位置，但这些空位是分布留空，**不等于已规划出连续通行走廊**。
6. 页面使用四张客户端真实人物 idle 图片，512/52 或 1024/104 均保持约 **9.846 世界单位画框**，按脚点对齐。没有为塞入地图而缩小人物。姓名是可开关的示意排版，未复现客户端 TMP 字形、长姓名、宠物或所有方向动作。

以上 5/6 间距、20% 留空、1.45 半径及试验尺寸均是**实验参数**，不是用户批准的新制作规格，也不是“不拥挤”的标准承诺。

表中两个百分比的分母都是**整张预览面积**；不能把 `largestComponentFraction` 读成“占已标地面的比例”。分量数量包含个别 1～2 像素小片；图像中的分离既可能来自真实阻隔，也可能来自屋顶遮挡、保守轮廓或栅格取整，不能直接宣称游戏中的路一定断了。

当前不在最大可见分量中的入口锚点：主城仓房入口；渔村北端远路；八仙岛南出口、南门南侧地面和莲池亭/两座连接木桥。八仙岛八处仙居入口均落在最大可见分量内。上述只是标注平面事实，门楼下穿行、桥梁、阶梯与屋檐遮挡区仍需单独核实。

因此，在本次**5 单位间距、留空 20%**实验中，三图同时放入 5000 个脚点的第一个已测组合是主城边长 1000、村岛各约 866.03。在 **6 单位间距**实验中，截至主城边长 1100、村岛各约 952.63，八仙岛仍未放足，尚没有三图同时满足的已测组合。

主城边长 700 的较小组合中，留空后主城可选 5224 个站位，渔村仅 2846、岛仅 2564；不能用主城单图的结果替代更小但同样要求 5000 人的村与岛。

这些数值描述的是已选择脚点网格，不代表“画面里 5000 个角色都互不遮挡”。宽服装、武器、人物高度、长姓名、随行宠物与组队聚集都可能造成遮挡或额外拥挤。

## 仍未通过的检查

- **真实导航与连续走廊：** 本次没有 Unity 导航、角色寻路、门洞碰撞、台阶高度、桥下/屋檐遮挡逻辑，也没有证明空置站位能组成连续通道。最大图像分量连通不等于角色带宽度可通过。
- **人物与建筑比例：** 将同一画布映射到更大的世界会同时扩大建筑和门洞。新生产合同的世界尺寸仍未确定，不能宣称简单拉大整图就保持建筑比例、清晰度和容量三者不变。
- **美术改动范围：** 本结果不足以要求现有主城、渔村或岛整图推倒重画。应先看真实比例近景、核实遮挡通路和实际热点，再决定是接入尺度调整、局部通路改动，还是补绘必要空间。
- **运行容量：** 未做 5000 人服务器同步、客户端角色更新、动画、寻路、可见性管理、目标手机帧率或内存测试。静态排下脚点不是运行容量保证。
- **正式交付：** 未修改已确认美术、分块生产规格、客户端世界范围或正式资源；未批准新的世界尺寸。
