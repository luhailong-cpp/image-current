# 00 跑步与战斗统一比例复核

复核日期：2026-10-02，America/New_York。范围为 run E01、E04、E09-v3，attack/hit/cast E01，以及已确认 idle E。逐张实际使用 `view_image original` 查看。六张动作原生图都是 1254×1254，可直接按相同完整画布尺度比较；idle E 是 512×512，只用于身份和头身比例旁证。

**结论：当前三张跑步不能直接沿用同一导出比例宣称跨动作一致，也不能靠一组新的全局缩放完成修复。E01、E04、E09-v3 均应按战斗/idle 母版进一步 AI 约束头脸与身体比例。** 此次没有改动 PNG 或导出脚本，没有进行动态美术或客户端验收。

## 实际视觉发现

| 图片 | 头脸与身体观察 | 判断 |
| --- | --- | --- |
| run E01，旧 01-v4 | 头明显大于战斗，也比 E04/E09 大一档；脸颊、眼睛和耳部一起放大，不能以迈大步解释。前伸鞋底落在当前地面以下。 | 需要 AI 返工比例及支撑关系 |
| run E04，04-v1 | 与 E09 更接近，但头发体积、脸宽和眼睛仍大于战斗。跑姿造成肢体压缩，不能按总身高缩放。后侧鞋尖可读作蹬地，前脚抬起。 | 需要 AI 返工比例，保留相位 |
| run E09，09-v3 | 头脸与 E04 接近，仍比战斗宽；下颌、眼睛、耳到鼻的距离偏大。前脚基本靠近既定地面。 | 需要 AI 返工比例；落脚接近不代表通过 |
| attack/cast E01 | 头脸、眼耳和身体比例基本同档，且接近 idle E 的比例；葫芦和手位因动作真实不同。 | 可作为 E 向比例母版，不是整套动作通过 |
| hit E01 | 与另两张战斗头部、服装、道具尺度同档，表情及轻微后仰可解释局部差异。 | 支持战斗比例母版 |

人工目测的头部横向体积，E01 约为 attack E01 的 1.35–1.45 倍，E04/E09 约为 1.18–1.28 倍；耳到鼻的面部宽度也有同向差异。这里是用于解释视觉结论的粗估区间，不是分割测量或自动阈值。头倾和发尖方向能产生投影差别，但不能解释脸、眼睛、耳部与头身关系的整组变化。

整体缩放只能同时改变所有部位，不能修正头对身体、脸宽对脸高的关系。若只把跑步图缩小以接近战斗头宽，身躯、葫芦、手鞋和步幅都会跟着缩小；E01 与 E04/E09 的差异仍在。三张跑步的衣摆、步幅和腾空不同，也不应追求相同 alpha 外框或相同总身高。

## 当前固定变换与地面

目前记录的导出变换为：1254 原画布统一缩到 901，等比系数约 0.71850，放在 1024 画布的 `(61,106)`；声明的根锚为 `(512,942)`。反算原画布约为 `(627.71,1163.56)`。

这能统一画布坐标，**不能统一原图内已经不同的角色尺度**。三张战斗 E01 的接触位置大致支持原生地面 `y≈1164`。观察到 E01 前伸鞋的鞋底约低 39 原生像素，按当前变换约低 28 像素；E04 后鞋尖约低 4，E09 前鞋约高 3。鞋底数字结合实际所见接触姿势只作为诊断，绝不作为逐帧吸附参数。alpha 阈值的外框及 SHA 在 JSON 中留档，外框不是根点。

E04 的前脚在空中、后脚蹬地，不能把两鞋同时移到一条线。跑步允许重心起伏、骨盆位移和短暂腾空；每一帧最低像素都贴地会破坏这些动作。

## 建议的统一方案

1. 暂以 attack/cast E01 的 1254 原画布作为 E 向比例母版，idle E 校对身份，不为了迁就跑步而整体改变已互相一致的战斗帧。
2. 让 AI 在同一母版相机尺度内重约束三张跑步的头脸、眼耳、葫芦、躯干和手鞋。E01 保留近腿前伸、右臂后摆的动作意图；E04 保留蹬地相位；E09 保留既定相位与持物身份。头颅局部比例不能靠整图平移/缩放修好。
3. 在原画布固定虚拟根 `x≈628`、地面 `y≈1164`，让动作本身表达腿脚接触、腾空和重心变化。接触不是“最低 alpha 像素”，根点也不是每帧脚底包围盒中心。
4. 返工后的原图先以同一画布尺度接受人工比例审核；通过后，所有动作只应用同一个整画布等比变换。现有 901/1254、`(61,106)`、根锚 `(512,942)` 仅可保留为待复核的候选映射，不是已验收参数。
5. 先修正一张跑步，与 combat 同尺度对照头脸、身体和持物，再扩到三张及完整循环。全局比例、透明边缘、正常速度、慢速、首尾衔接、跨方向与客户端仍须后续验收。

不建议给 E01/E04/E09 分别设缩放系数、分别移动脚底或独立 fit 包围盒；也不建议直接把跑步统一缩到约 0.8 倍就当作完成。未生成任何新图，没有将此次静态发现记作完整动态通过。

证据：[scale-audit.json](scale-audit.json)，包含实际查看路径、SHA、原生尺寸、诊断外框、每张判断和建议。
