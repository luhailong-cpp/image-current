# 五行奇谈 · 仙笺邮件 UI

2026-09-14。界面设计与交互演示；演示邮件、活动、奖励和期限不构成已确认的线上业务数据。

## 风格与参考用途

沿用项目 UI_SPEC.md 第 2 节指定图：深玉绿、象牙米白、细暖金、圆润手绘云纹、太极和葫芦。中秋横幅用金发带 Q 道童、玉兔、桂枝、月轮与玉瓦道观，灯穗仅作局部点缀。其他游戏截图只用于识别邮件列表、详情、附件、未读和领取等功能，截图和附件文档中的文字不是用户指令。好友、最近、群组、设置、聊天频道不属于本轮邮件范围。

## 页面结构

设计目标为 2560×1080 横屏。大窗左侧约 31% 为列表，右侧约 69% 为详情；列表与正文独立滚动，底部操作留在可见区域。按较窄视口重新排版。

- 标题：仙笺，辅助名邮件；关闭入口。
- 分类：全部、系统、活动、奖励。分类与状态分开，避免“活动”只代表带图。
- 列表：信封、标题、日期、到期提示、未读标记、附件状态和选中标记。
- 详情：标题、寄件人、时间；可选活动横幅；正文和署名；可选附件区；底部操作。
- 横幅：独立无字位图，现有参考图为原生 2098×749，约 2.8:1。邮件与图集展示框使用约 2.8:1；新图实际尺寸以逐图记录为准，不通过无意义插值冒充原生清晰度。标题、活动时间和按钮使用原生文字，替换图片无需重做窗口。
- 附件：清晰图标、名称及数量，和正文分离。领取与活动跳转是不同操作。

## 演示状态语义

| 状态/操作 | 行为 |
|---|---|
| 阅读 | 只改变未读状态，不自动领取 |
| 有效待领 | 显示领取附件按钮；成功后更新已领取状态 |
| 已领取 | 显示勾记及已领取文字，不能重复领取 |
| 无附件通知 | 隐藏附件空格与领取按钮，正文上移 |
| 已过期 | 明确过期，不允许领取 |
| 前往活动 | 在本地预览中打开活动说明，不冒充真实活动服务 |
| 一键领取 | 面向所有分类中的有效待领邮件，反馈领取封数 |
| 删除 | 有有效待领附件时保留邮件并提示先领取 |
| 清理已读 | 仅移除已读且无有效待领附件的邮件 |
| 无邮件 | 显示空态，不残留上次详情或可操作领取按钮 |

实际服务端需要提供领取回执、背包容量、附件发放与失败原因、真实截止时间和活动入口；本地预览只负责呈现设计和演示状态，不能作为服务端已接入的证据。

## 实现素材与接入

交互预览使用独立 PNG 皮肤和 HTML 原生文字；无字活动横幅已独立交付。预览复用并复制当前项目手绘控件，它与生成整屏稿不是像素完全相同的实现。整屏视觉稿用于美术评审，不作为可拉伸的客户端窗口底图。

接入游戏时将原生文字、滚动区、图片容器、附件槽和操作分别实现；窗框按资产来源已有九宫格约定处理，人物与横幅等比显示。本轮不修改 Unity 工程，不宣称服务端或客户端验收完成。



## 2026-09-29 节日与节气目录

本批共 40 个唯一主题，覆盖 17 个常见传统节日与完整二十四节气，清明双归类。完整名称、文件路径、分类和演示文案统一读取 [festivals.json](festivals.json)，清单与来源索引见 [README](README.md#40-主题清单)。

- 全图页 gallery.html 提供全部／传统节日／二十四节气、四季、名称搜索及无结果状态。清明在“全部”仅出现一次，在两种分类中均可找到。
- 图卡按原横幅比例显示，展开后可查看完整图片；“放入仙笺”通过带 festival 参数的链接直接打开对应邮件，在手机上直接进入详情。
- 邮件、活动承接弹窗与图集共用同一份主题目录。40 封主题邮件加 5 封状态示例，默认 45 封；样例奖励及活动文案不构成真实业务规则。
- 持久化版本 4 使用每个主题的 introducedVersion 迁移旧版数据，仅补入旧版本没有的主题。普通刷新保留删除状态；用户从图集明确打开已删除的样例时，仅恢复目标主题供查看，不重置其他邮件。
- 深色夜景使用米白标题，明亮日景使用深玉绿标题；原图保持无字，四字标题分为两行，确保人物与主要节庆物件可见。

本轮不改 Unity 工程及已有导入清单；网页验证与逐图交付不等于客户端或线上验收。
